# Contributing to AI-Based Purchasing Tendency

Thank you for your interest in contributing to the **AI-Based Purchasing Tendency** project.

Contributions, suggestions, improvements, bug reports, documentation updates, and AI/ML experiments are welcome.

---

## 📌 Project

**AI-Based Purchasing Tendency**

The project explores AI-driven retail intelligence using:

* Graph Neural Networks (GNN)
* SASRec sequential recommendation
* Customer purchasing behavior analysis
* Purchasing community discovery
* Location-wise demand analysis
* Personalized recommendations

---

## 🚀 Getting Started

### 1. Fork the Repository

Create your own fork of the repository on GitHub.

### 2. Clone Your Fork

```bash
git clone https://github.com/Dhonijd12345/AI-Based-Purchasing-Tendency.git
```

```bash
cd AI-Based-Purchasing-Tendency
```

### 3. Create a Virtual Environment

Windows:

```bash
python -m venv venv
venv\Scripts\activate
```

Linux/macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 4. Install Dependencies

```bash
pip install -r requirements.txt
```

---

## 🌱 Create a Feature Branch

Use a descriptive branch name:

```bash
git checkout -b feature/your-feature-name
```

Examples:

```text
feature/recommendation-improvement
feature/demand-analysis
feature/data-preprocessing
feature/dashboard
fix/data-loading
docs/readme-update
```

---

## 💻 Development Guidelines

Please follow these practices:

* Keep code readable and maintainable.
* Use meaningful variable and function names.
* Avoid unnecessary complexity.
* Add comments where logic is non-obvious.
* Keep dependencies synchronized with `requirements.txt`.
* Do not commit API keys or credentials.
* Do not commit private customer data.
* Test changes before creating a pull request.
* Update documentation when functionality changes.

---

## 🧪 Testing

Before submitting changes, verify that:

* The application starts correctly.
* Data loading works as expected.
* Existing functionality is not broken.
* New functionality has been tested.
* No sensitive information is included.

---

## 📊 Data Guidelines

If working with customer or transaction data:

* Use public, synthetic, or anonymized datasets.
* Never upload personally identifiable information.
* Never commit confidential business data.
* Never include passwords, tokens, or API keys.

---

## 📝 Commit Messages

Use clear commit messages.

Good examples:

```text
feat: improve purchasing recommendation logic
fix: resolve data preprocessing issue
docs: update project documentation
refactor: simplify model pipeline
test: add recommendation validation
```

Avoid vague messages such as:

```text
update
changes
final
new
test
```

---

## 🔀 Pull Requests

Before opening a pull request:

1. Make sure your branch is updated.
2. Test your changes.
3. Review the changed files.
4. Update documentation if required.
5. Provide a clear pull request description.

A pull request should explain:

* What was changed?
* Why was it changed?
* How was it tested?
* Are there any limitations?

---

## 🐛 Bug Reports

When reporting a bug, provide:

* Description of the problem.
* Steps to reproduce it.
* Expected behavior.
* Actual behavior.
* Python version.
* Operating system.
* Relevant error message or traceback.

---

## 💡 Feature Requests

For new features, explain:

* The proposed feature.
* The problem it solves.
* Expected behavior.
* Possible implementation approach.
